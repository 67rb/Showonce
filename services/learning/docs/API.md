# Proposed API v1

Base URL: `http://127.0.0.1:8000`. JSON field names use snake_case.
IDs are opaque strings; a step ID is stable within its lesson. Positions start at 1.
Dates use UTC ISO 8601. Responses are JSON except image retrieval and HTTP 204.

## Endpoints

| Method | Path | Access | Response |
|---|---|---|---|
| GET | `/health` | Public | Health, API version, mock mode |
| GET | `/v1/lessons` | Public | `{"lessons": [...]}` |
| POST | `/v1/lessons` | Public | 201 lesson; processing is synchronous |
| GET | `/v1/lessons/{lesson_id}` | Public | Lesson |
| POST | `/v1/sessions` | Public | 201 progress plus one-time access token |
| GET | `/v1/sessions/{session_id}` | Session bearer token | Progress; also resumes session |
| GET | `/v1/sessions/{session_id}/progress` | Session bearer token | Progress |
| POST | `/v1/sessions/{session_id}/submissions` | Session bearer token | 201 submission and progress; 200 on replay |
| GET | `/v1/sessions/{session_id}/submissions` | Session bearer token | `{"submissions": [...]}` |
| GET | `/v1/sessions/{session_id}/usage` | Session bearer token | `{"events": [...]}` |
| GET | `/v1/sessions/{session_id}/submissions/{id}/image` | Session bearer token | Original image bytes |
| DELETE | `/v1/sessions/{session_id}/submissions/{id}/image` | Session bearer token | 204, including repeat deletion |

Session endpoints require `Authorization: Bearer <access_token>`.
The token is returned only at creation. Save it with the session ID for resume.
Losing the token loses access: account-based recovery is not implemented.
No token belongs in a query string. Lessons are public: do not submit private
signed URLs or confidential source content to this version.

## Lesson and step

Request to `POST /v1/lessons`:

```json
{"source_url": "https://example.com/tutorial"}
```

Response shape (abbreviated to one step):

```json
{
  "id": "lesson_opaque",
  "title": "Sample paper fold practice",
  "source_url": "https://example.com/tutorial",
  "category": "origami",
  "content_origin": "mock_sample",
  "practice_restrictions": ["Sample content; instructions were not extracted from the supplied link."],
  "safety_notice": "Practice feedback is not certification of safety.",
  "steps": [
    {
      "id": "fold_01",
      "position": 1,
      "instructions": "Place a square sheet of paper on a flat surface.",
      "expected_visual_result": "A complete square sheet is visible on a flat surface.",
      "assessment_criteria": ["All four corners are visible", "Paper lies flat"]
    }
  ]
}
```

The submitted `source_url` is authoritative: the backend preserves it even when
the provider omits or replaces it. `practice_restrictions` and
`assessment_criteria` must be arrays of nonblank strings; malformed elements
return 502 `invalid_lesson` before any lesson is saved.

The seed lesson ID is `lesson_sample_origami`; it has two steps, `fold_01` and
`fold_02`. Repeated tutorial requests create independent lessons. Category is
currently metadata, not a restricted enum. Trade lesson content and category
navigation need team agreement; no trade instruction is generated by this mock.

## Session and progress

Request to `POST /v1/sessions`:

```json
{"lesson_id": "lesson_sample_origami"}
```

Creation returns:

```json
{
  "session_id": "session_opaque",
  "lesson_id": "lesson_sample_origami",
  "access_token": "save-this-secret-for-resume",
  "status": "active",
  "current_step_id": "fold_01",
  "completed_step_ids": [],
  "total_steps": 2,
  "updated_at": "2026-10-27T14:00:00+00:00"
}
```

Subsequent progress responses omit `access_token`. Completed sessions have
`status: "completed"`, `current_step_id: null`, and all completed step IDs.
A new session always starts from step 1; resume by retrieving the existing one.

## Photo submission and assessment

`POST /v1/sessions/{session_id}/submissions` requires
`Content-Type: application/json` and `Idempotency-Key: <unique-key>`.
Generate a fresh key for each intentional new submission and reuse it when
retrying the same network request. Keys are scoped to a session, 1–128 characters.

```json
{
  "step_id": "fold_01",
  "mime_type": "image/png",
  "image_base64": "<raw base64, without a data URL prefix>",
  "mock_result": "retry"
}
```

Only PNG, JPEG, and WebP are accepted, up to 5 MiB of decoded image bytes.
Request bodies have a 7,100,000-byte cap. `mock_result` accepts `pass`, `retry`,
or `uncertain`, defaults to `uncertain`, and is forbidden outside mock mode.

```json
{
  "submission": {
    "id": "sub_opaque",
    "session_id": "session_opaque",
    "step_id": "fold_01",
    "status": "assessed",
    "created_at": "2026-10-27T14:01:00+00:00",
    "assessment": {
      "result": "retry",
      "feedback": "Mock result: adjust your work and try again.",
      "corrections": ["Check: A complete square sheet is visible on a flat surface."],
      "provider": "mock",
      "model": "fake-assessor-v1",
      "is_mock": true,
      "usage": {"estimated_cost_usd": 0, "input_tokens": null, "output_tokens": null}
    }
  },
  "progress": {
    "session_id": "session_opaque",
    "lesson_id": "lesson_sample_origami",
    "status": "active",
    "current_step_id": "fold_01",
    "completed_step_ids": [],
    "total_steps": 2,
    "updated_at": "2026-10-27T14:00:00+00:00"
  },
  "replayed": false
}
```

Submission status is `processing`, `assessed`, or `failed`. Assessment is null
until assessed. Provider processing runs outside the SQLite write transaction.
The initial POST waits for assessment; a concurrent replay may return
`processing`. Poll session submission history until assessed or failed. Progress
is always authoritative server state, not a client-side increment.

Same key plus same content returns the existing submission with `replayed: true`.
Same key with different content returns 409. Replay progress reflects current
session state, which may have advanced further since the original response.
A new key for an already completed step returns 409. A different request while
assessment is pending returns 409 `assessment_in_progress`.

If the provider fails, the submission becomes failed and progress stays put.
If saving a successful assessment fails, the API returns 503 `finalization_failed`.
Progress updates roll back. The server queues a failed-state cleanup and retries
it on subsequent submission, progress, or history requests when storage recovers.
The provider is not called again during cleanup. Check history before intentionally
retrying with a new key. A lost HTTP response should first be retried
using the original key or checked in history; do not immediately create new work.

## Error contract

```json
{
  "error": {
    "code": "step_not_current",
    "message": "Submit only for the session's current step.",
    "retryable": false
  }
}
```

| HTTP | Codes | Frontend response |
|---|---|---|
| 400 | `invalid_json`, `invalid_body` | Correct request |
| 401 | `invalid_session_access` | Recover saved token or start a new session |
| 404 | `lesson_not_found`, `image_not_found`, `route_not_found` | Show unavailable state |
| 409 | `step_not_current` | Refresh progress |
| 409 | `idempotency_conflict` | Fix key reuse; avoid automatic retry |
| 409 | `assessment_in_progress` | Wait and retrieve history |
| 413 | `image_too_large`, `body_too_large` | Resize or retake |
| 415 | `unsupported_content_type` | Send application/json |
| 422 | `unsupported_link`, `invalid_image`, `invalid_step`, `invalid_lesson_id`, `invalid_mock_result`, `invalid_idempotency_key` | Show actionable correction |
| 502 | `assessment_failed` | Check saved failure; retry with a new key |
| 502 | `invalid_lesson` | Provider output needs correction |
| 503 | `finalization_failed` | Retrieve history after storage recovers; retry failed work with a new key |
| 500 | `internal_error` | Retrieve current state before deciding to retry |

## Hashir's provider boundary

Replace implementations in `backend/showonce/providers.py`; wire instances into
`Backend` in `server.py`. A real adapter must not trust caller-selected mock
outcomes. `TutorialProvider.process(source_url)` returns lesson fields above,
without the ID or safety notice, which the backend adds. The backend also sets
`source_url` from the validated request rather than trusting provider output. Set `content_origin` to
an accurate source descriptor. Real tutorial extraction must enforce safe practice
content and supported-source policy before returning lessons.

`AssessmentProvider.assess(image=bytes, mime_type=str, step=dict, scenario=str)`
returns the assessment object above. `scenario` is for mocks only. The backend
owns submission IDs, storage, and progress. Adapters own provider calls, deadlines,
and model-specific translation, with finite retry limits. They should report
actual provider/model names and usage; unknown costs/tokens must be null rather
than zero. Never return API credentials or raw provider diagnostic secrets.

There is no external callback or live-video endpoint in v1. Introduce a versioned
contract for those features after agreeing ownership, transport, and processing.
